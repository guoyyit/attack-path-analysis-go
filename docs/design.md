# 攻击路径分析服务 — 设计说明

## 1. 数据模型

- **资产 `Asset`**：图节点。`External=true` 表示攻击者控制的外部入口点；
  `Critical=true` 表示关键资产；`Attributes` 为任意资产属性，参与变更判定。
- **连通规则 `ConnectivityRule`**：有向信任边 `From -> To`。
  `Capabilities` 表示攻击者控制 `From` 后对 `To` 获得的能力，例如
  `network`（默认可达）、`ssh`、`admin`。空能力集合等价于 `["network"]`。
- **漏洞 `Vulnerability`**：附着在某资产上。`Exploitability` 是该利用步骤
  独立的成功概率 `p ∈ [0,1]`；`Preconditions` 是利用该漏洞所需的全部能力，
  必须由抵达它的连通规则能力集合所包含。

### 漏洞可利用性（攻击边）

存在从资产 `A` 经规则 `r`、漏洞 `v` 攻陷资产 `B` 的一步，当且仅当：

1. `A` 已被攻陷（或 `A` 本身就是外部入口）；
2. `r.From == A` 且 `r.To == B`，且 `v.Asset == B`；
3. `v.Preconditions ⊆ r.Capabilities`。

## 2. 可达性推导（含环路终止）

攻陷集合从所有外部入口资产开始，按确定性顺序（资产 ID 排序）做单调不动点
迭代：每轮只可能新增资产，因此图中存在任意环路时也必然在至多
`资产数` 轮内终止，结论确定。

## 3. 攻击路径枚举

- 路径为从入口（或查询指定起点）到目标的**简单路径**（不重复经过资产），
  DFS 中用访问集合切断回边，因此环路不会产生无限或重复路径，路径数量
  有上界。
- 每一步取漏洞的 `Exploitability`；一条路径的概率为各步概率之积
  `P(path) = Π p_i`（各步视为条件独立的串联成功）。
- 路径先按概率降序，再按规范化路径键
  （`start > to:rule:vuln ...`）升序做确定性平局裁决。

## 4. 风险计算模型

单条路径成功概率：

```
P(path) = ∏ exploitability(step)
```

资产整体风险按多路径“至少一条独立路径成功”聚合（噪声或 / noisy-OR）：

```
risk(asset) = 1 - Π_path (1 - P(path))
```

聚合前对路径去重并按确定性顺序排序，乘积形式与求值顺序无关，因此结果
**可复现且与输入顺序无关**。外部入口资产风险固定为 `1`；不可达资产没有
风险记录（风险查询返回 `null` / 不出现在结果中）。

## 5. 增量更新语义

更新以一批 `Op` 为单位，操作种类：

| 操作 | 语义 |
|------|------|
| `UpsertAsset` | 新增或整体替换资产 |
| `DeleteAsset` | 删除资产，并级联删除引用它的规则与其上的漏洞 |
| `UpsertRule` | 新增或整体替换连通规则 |
| `DeleteRule` | 删除连通规则 |
| `UpsertVuln` | 新增或整体替换漏洞 |
| `DeleteVuln` | 删除漏洞 |

### 只重算受影响范围

1. 为每个变更收集**种子资产**（资产本体；规则的 `From`、`To`；漏洞所属
   资产；删除时用变更前的端点）。
2. 沿**新图**的规则边做前向闭包，得到“受影响区域”。区域之外的攻陷结论
   不可能发生变化（删除只会移除顺流证据），直接复用旧结论。
3. 将区域内的攻陷结论重置，在全图上重做不动点（区域外事实固定、边不会
   从区域内流向区域外节点），再只对区域内资产重算路径与风险。

该算法对新增、修改和删除都成立。随机差分测试对数百轮随机增删改逐一比对
“增量结果”与“从零全量重建结果”，攻陷集合、每个资产的得分与路径集合完全
一致（见 `incremental_test.go`）。

### 原子性与校验

一批操作先针对旧快照完成全部校验（引用的资产必须存在、概率在 `[0,1]`
等）与计算：任何一条非法则整批拒绝，旧状态不变；成功后一次性原子切换。

## 6. 带约束的路径查询

`Query{Target, StartAssets, MustInclude, Exclude, MaxSteps}`：

- `Target` 为空时查询所有关键资产；指定时只查该资产。
- `StartAssets` 限定起点集合；为空时使用全部外部入口。
- `MustInclude`：路径必须经过这些资产。
- `Exclude`：路径不得经过这些资产（含起点/目标）。
- `MaxSteps`：步骤数上限；`0` 表示不限（枚举本身被资产数限定）。

结果按风险降序、资产 ID 升序排列；无路径时返回明确的空结果 `[]`。

## 7. 并发与快照一致性

每个已提交版本是一张**不可变快照**。查询通过 `atomic.Pointer` 读取当前
快照并在整个求值期间持有它；更新在互斥锁内构造一张全新快照，计算完成后
再做一次原子指针交换。因此读者无需阻塞写者，且在更新进行中永远只会看到
更新前或更新后的完整状态，不可能读到部分更新。

## 8. 持久化与崩溃恢复

采用只追加的预写日志（WAL，`attackpath.wal`）：

- 每批提交写成一条带帧的记录：`seq(8) | 长度(4) | JSON 载荷 | CRC32(4)`。
- 顺序为：先校验并算出新快照 → 追加并 `fsync` 落盘 → 原子切换内存快照
  （持久化先于可见性）。
- 重启时从头回放所有完整记录。末尾若存在长度不足或 CRC 不符的残帧
  （即崩溃发生在记录写完之前的“部分写入”），会被识别并截断，绝不生效；
  其之前的已提交记录全部恢复，不丢已提交数据。
- 被拒绝的批次在落盘前即返回错误，不会写入日志。

## 9. HTTP 接口

```
POST /apply            {"ops":[...]}                 原子提交一批变更
POST /query            查询体见下，返回风险结果数组（无解为 []）
GET  /risk/{id}        单资产聚合风险（不可达为 null）
GET  /compromised/{id} 是否可被攻陷
GET  /healthz          存活探针
```

查询请求体：

```json
{
  "target": "db",
  "start_assets": ["internet"],
  "must_include": ["jumpbox"],
  "exclude": ["maintenance-host"],
  "max_steps": 6
}
```

操作（`/apply` 中 `ops` 元素）：

```json
{"kind":"upsert_asset","asset":{"id":"...","external":false,"critical":true,
 "type":"host","attributes":{"k":"v"}}}
{"kind":"delete_asset","asset":{"id":"..."}}
{"kind":"upsert_rule","rule":{"id":"...","from":"a","to":"b",
 "capabilities":["network","ssh"]}}
{"kind":"delete_rule","rule":{"id":"..."}}
{"kind":"upsert_vuln","vuln":{"id":"...","asset":"b",
 "exploitability":0.5,"preconditions":["network"]}}
{"kind":"delete_vuln","vuln":{"id":"..."}}
```
